# Acolyte

Unofficial mobile app (Android and iOS) for the self-hosted media app HolyArrs, talking to the user's own server over its `/api/v1` JSON API. Kotlin Multiplatform: all logic lives in `shared/`; `androidApp/` (Compose) and `iosApp/` (SwiftUI) only render state and forward input. The README has the overview, build steps and release process.

## Commands

```bash
source ~/.sdkman/bin/sdkman-init.sh && export ANDROID_HOME=~/android-sdk

./gradlew androidApp:assembleDebug androidTvApp:assembleDebug
./gradlew shared:allTests androidApp:testDebugUnitTest androidTvApp:testDebugUnitTest   # on Linux the iOS test targets are skipped
./gradlew shared:ktlintCheck androidCommon:ktlintCheck androidApp:ktlintCheck androidTvApp:ktlintCheck   # fix with the same modules' ktlintFormat
./gradlew androidApp:lintDebug androidCommon:lintDebug androidTvApp:lintDebug
./gradlew shared:testDebugUnitTest --tests '*ApiContractTest*'   # client endpoints vs api/openapi.json
python3 scripts/ios/check-strings.py                        # iOS string tables
```

Live contract test against a real server (Docker, no sudo needed):

```bash
eval "$(scripts/api/live-server.sh)"        # boots holyarrs/holyarrs:<api/VERSION>, sets it up, exports ACOLYTE_LIVE_*
./gradlew shared:testDebugUnitTest --tests '*LiveContractTest*'
scripts/api/live-server.sh stop
```

CI runs the same (`android.yml`, `ios.yml`, `api.yml`). Kover coverage is informational only. Kotlin style comes from `.editorconfig` (ktlint official, 4 spaces, 140 columns).

## Modules

- **`shared/`** (package `ch.orellbuehler.acolyte`): HTTP client, sign-in, session, bootstrap, live updates, image URLs, navigation rules and one presenter per feature. `AcolyteSdk` is the single entry point. Keep what the UIs do not need `internal`. On iOS it is the `shared` framework through SKIE. Kotlin is bumped only together with SKIE (Dependabot ignores Kotlin).
  - `api/`: `ApiClient` (the only code that makes HTTP requests), `Endpoint` + `EndpointGroup` (the endpoint registry), `<Feature>Endpoints.kt` (one `data object` per area), `api/model/` (the `@Serializable` wire models), `ApiError`/`ApiErrorCode`, `SessionCookies`.
  - `session/`: `SessionManager` (`SessionState`: Restoring, SignedOut, SignedIn(Account)), `SignInFlow` (connect, password, two-factor, Jellyfin/Emby, API key), `Account` (role, permissions, parts, tabs, More groups), `SecureStore` (`AndroidSecureStore`: Keystore AES-GCM; `KeychainStore`), `ServerAddress`.
  - `nav/Section.kt`: every section of the app with the spec operation that gates it. `feature/`: `LoadStatus`/`Phase`/`Tone` and one package per feature (`feature/health/HealthPresenter`). `live/`: SSE client for `<base>/live`. `image/`: `Images` (URLs + auth headers), `ArtPlaceholder`.
- **`androidApp/`**: Compose and Material 3, one package per feature under `ui/`. Navigation in `ui/nav/` (`Routes.kt`, `Destinations.kt`, `AppNavHost.kt`), shared UI in `ui/components/`, the only palette in `ui/theme/Theme.kt` (in `androidCommon`). Unit tests in `androidUnitTest`.
- **`androidCommon/`** (Android library, namespace `ch.orellbuehler.acolyte.common`): what the phone and the TV app both need, in the packages they import it from: `ui/theme/Theme.kt` (`Palette`, `AcolyteColors`, the phone theme), `ui/components/ServerImage.kt` (`ServerImage`, `ArtPlaceholder`), `ui/components/Errors.kt` (`errorText`, `signInErrorText` and their strings: `error_*` and `signin_error_*`, English and German), `ui/LocalSdk.kt`, `ui/ServerImageLoader.kt` (the Coil loader that adds the server's cookie or API key), `ui/SessionViewModel.kt`, the brand mark, the launcher icon and the network security config. Keep it small: move something here only when both Android apps use it, keep its package, and reference its resources as `ch.orellbuehler.acolyte.common.R` (`import ... .common.R as CommonR` last in the import list, ktlint puts aliases at the end).
- **`androidTvApp/`** (Android TV, package `ch.orellbuehler.acolyte.tv`): see "Android TV UI".
- **`iosApp/`**: SwiftUI, project generated by XcodeGen from `iosApp/project.yml` (`*.xcodeproj` and `Acolyte/Info.plist` are generated and gitignored; add Info.plist keys in `project.yml`). **Views never `import shared`**: only `iosApp/Acolyte/SDK/` does. It maps shared types into the plain `Sendable` Swift models in `SDK/Models.swift`, and views use those. Routes in `App/Routes.swift`, shared UI in `Support/Components.swift`, the only palette in `Support/Theme.swift`.
- **`AcolyteTV` (Apple TV)**: a second XcodeGen target in `iosApp/project.yml` (tvOS 18, same bundle id, own scheme) with its views in `iosApp/AcolyteTV/` and its own asset catalog (brand assets generated by `scripts/ios/make-tvos-assets.py`). It compiles, from `Acolyte/`, only the files in its `includes` list: the `SDK/` layer, `Support/{Theme,L10n,Format,ErrorText,AuthImage,SectionText}.swift`, the Foundation-only stores and word tables (`Connect/ConnectStore`, `Discover/DiscoverStores`, `Discover/DiscoverText`, `Home/HomeText`, `Requests/RequestsStores`, `Requests/RequestsWords`, `Title/TitleStore`, `Title/TitleText`, `Music/MusicRoutes`, `Downloads/{CalendarStore,DownloadsStore,DownloadsText,DlTitleLinkRoute,DlToastModel}`, `Requests/AskLinesView`) and the string tables. A new file in `Acolyte/` that tvOS should share must be added there and must not touch UIKit-only or iOS-only API (split such code into its own file instead of using `#if`); views stay per platform. `shared` has the tvOS targets and the platform code lives in `appleMain` (Keychain, Darwin engine, file/time helpers); only `platformName` differs in `iosMain` / `tvosMain`.
- **`api/`**: `openapi.json` is the spec of the HolyArrs release in `VERSION`, never edited by hand.

## How the client talks to HolyArrs

- Base URL = what the user typed, normalised by `ServerAddress` (scheme added, `/login` or `/api/v1...` stripped, URL base such as `/holyarrs` kept). Every path, `/live` and image paths included, goes under it.
- Sign-in: password (`POST /auth/login`), two-factor step with the ticket (`POST /auth/login/two-factor`, the code field also takes backup codes), Jellyfin/Emby (`POST /auth/media-server/{kind}`), or an API key (`X-Api-Key`; only people with `settings` can make one, so cookie sessions are the default). Plex PIN and OIDC are not implemented yet; the sign-in screen names them when the server offers them.
- Cookie sessions: the cookie is `holyarrs_session` or `holyarrs_session_<port>` and rotates hourly on any response, so `SessionCookies` persists every `Set-Cookie` (the image loaders hand theirs back through `Images.storeCookies`). Writes send `X-CSRF-Token`; a 403 about CSRF re-reads `/auth/me` and retries once. The app sends no `Origin` header (a mismatching one is refused).
- A 401 on a non-auth route signs out (`SessionState.SignedOut(expired = true)`); the server URL and name stay for the next sign-in. `403 code:"reauth"` is `ApiErrorCode.REAUTH`: ask for the password and call `SessionManager.reauth(password, code)`, then retry. `409 "this part is off"` is `PART_OFF`, `"hands-off mode is on"` is `HANDS_OFF` (`ApiError.part` and `.text` carry the server's fields).
- Server error sentences are English: localise `ApiError.code` / `SignInError.code` in the UI and show `message` only as a fallback.
- Bootstrap after sign-in and on foreground: `/auth/me`, `/parts`, `/my/profile`, and `/app/about` only for people with `settings` (others get no server version). The last bootstrap is stored, so a restart shows the app at once and refreshes in the background.
- Live updates: SSE at `<base>/live`, envelope `{topic, data}`, heartbeat every 15 s, resume with `Last-Event-ID`, `resync` means reload everything. Presenters collect `api.live` in a `watch()` that the UI runs only while the screen is visible.
- Images: pass the picture value from the payload to `ServerImage` (Android) or `AuthImage` (iOS). `Images.url` rewrites TMDB URLs to the server cache (`/api/v1/artwork/tmdb/<size>/<file>`) and prefixes app paths; `Images.headers` adds the cookie or API key for server URLs only.
- JSON: models follow the real Go structs and TypeScript types, not only the spec (the spec is thin: `/auth/me` lists 5 of 23 fields). Every property has a default (`""`, `0`, `false`, `emptyList()`, `null`), names come from `@SerialName` per property (some endpoints answer Go-cased `ID`, `State`, `At`: never use a global naming strategy). Decoding ignores unknown keys and coerces `null` to the default.

## Adding an endpoint

1. Read the operation in `api/openapi.json` (`x-holyarrs-permission`, `x-holyarrs-part`, parameters, schemas). When the response is untyped (`{type: object}` or no schema, about 40% of operations), read the Go handler in `app/backend` and the TypeScript types in `app/frontend/src/lib` of the HolyArrs repo for the real shape.
2. Models go in `shared/src/commonMain/kotlin/ch/orellbuehler/acolyte/api/model/<Area>.kt`: `@Serializable data class`, `@SerialName` for every snake_case or Go-cased field, a default on every property. Use `String` for enum-like values (unknown values must not break decoding).
3. Declare the endpoint in `api/<Area>Endpoints.kt`, in a `data object <Area>Endpoints : EndpointGroup()` in package `ch.orellbuehler.acolyte.api` (the sealed hierarchy is how the contract test finds it):
   ```kotlin
   internal data object TitleEndpoints : EndpointGroup() {
       val list = get("/api/v1/titles", TitleList.serializer(), Need.SIGNED_IN, Part.MEDIA, query = listOf("q"))
       val update = put("/api/v1/titles/{id}", TitleUpdate.serializer(), Title.serializer(), Need.MANAGE_LIBRARY, Part.MEDIA)
   }
   ```
   The path is the spec's path template verbatim (same `{param}` names); `need` and `part` are the spec's `x-holyarrs-permission` (or `PUBLIC` when `security` is empty) and `x-holyarrs-part`; `query` lists every query parameter the app sends. Use `NoContent` for 204 answers.
   File uploads: make the (internal) body class implement `FormBody` (`api/FormBody.kt`); `ApiClient` sends it as `multipart/form-data` when `formFiles` is not empty (see `AddTorrentsBody`).
4. Call it through `Api`/`ApiClient` only: `api.result(TitleEndpoints.update, body, "id" to id)` returns `ApiResult` (presenters), `call(...)` throws `ApiException`. Path and query parameters are passed as `name to value` pairs; an undeclared name throws.
5. Run `./gradlew shared:testDebugUnitTest --tests '*ApiContractTest*'`. It fails for a path or method not in the spec, a plugin route, a deprecated operation, a wrong need/part, a path or query parameter the spec does not list, a missing required query parameter, a request body that contradicts a typed schema (missing required fields, unknown fields, wrong types) and a response model that contradicts a typed schema (wrong types, a field without default the spec does not guarantee). Extra optional response fields and untyped responses pass (they show as notes in the summary). When the spec itself is wrong, add the exact failing line to `KnownSpecGaps.problems` (androidUnitTest/.../contract) with the reason; stale entries fail too.
6. Add a MockEngine test in `shared/src/commonTest` (see `FakeServer`, `HealthPresenterTest`). Read endpoints without path parameters are also called by `LiveContractTest` against the real server with strict decoding.

Two more checks in the same test keep the registry complete: only `api/*Endpoints.kt`, `api/ApiClient.kt` and `nav/Section.kt` may contain `/api/v1/` strings (Kotlin and Swift sources of all modules), and only `ApiClient.kt` may import Ktor's request API.

## Adding a feature (both platforms)

Every feature ships on Android and iOS. Implement both, or say in the commit message which one is deferred. Copy the Status (health) feature:

1. **Shared presenter** in `shared/.../feature/<area>/<Name>Presenter.kt`: a public `data class <Name>State(val status: LoadStatus = LoadStatus(), ...)` with plain fields and derived getters, and a class with an `internal` constructor taking `Api`, a `StateFlow<State>`, suspend actions (`load()` loads once, `refresh()`, writes) guarded by a `Mutex`, and `watch()` for live topics. Failures go into the state (`status.failed(error)` keeps loaded data and shows a banner), never thrown. Add a factory to `AcolyteSdk` (`fun health(): HealthPresenter`). Add a repository only when two presenters need the same cached data.
2. **Android**: `ui/<area>/<Name>ViewModel.kt` (holds the presenter, `init { load() }`, actions in `viewModelScope`, `suspend fun watch()`), `ui/<area>/<Name>Screen.kt` using `ScreenScaffold` + `StatusContent` (loading, error, empty, pull-to-refresh) and run `watch()` with `repeatOnLifecycle(STARTED)`. Register the route: replace the section's `PlaceholderScreen` in `ui/nav/AppNavHost.kt`; new detail screens get a `@Serializable` route in `Routes.kt` and a `composable<...>` there.
3. **iOS**: a driver in `SDK/Drivers.swift` (`@unchecked Sendable`, wraps the presenter, `watch(deliver:)` maps state with `Mapping`), Sendable models in `SDK/Models.swift`, mapping in `SDK/Mapping.swift`, a `factory` in `SDKClient`, a `@MainActor @Observable` store and a view in `<Area>/`. The view uses `StatusContent`, `.refreshable`, and `.task { await store.watch() }`, `.task { await store.load() }`, `.task { await store.followLive() }`. Register it in `SectionScreen` (`App/Routes.swift`).
4. Detail screens other areas open are shared routes: Android `Routes.<name>(...)` in `ui/nav/Routes.kt` (e.g. `Routes.title(kind, tmdb)`, `Routes.libraryTitle(id)`), iOS `Route.<case>` in `App/Routes.swift`, pushed with `NavigationLink(value:)` and resolved by `RouteScreen`. Endpoints of another area that a feature needs live in its own `<Area>SupportEndpoints` group until that area exposes them. Cross-area navigation goes through named routes. Android: `Routes.<name>(...)` in `Routes.kt` returns the `@Serializable` route; sheets are `dialog<...>` destinations that draw `RouteSheet` (`ui/requests/AskSheets.kt`). iOS: `enum Route` in `App/Routes.swift`; every tab stack is a `RoutedStack`, views call `@Environment(\.openRoute)` (sheet routes such as `.ask` present, others push) and `RouteScreen` maps each case to its view. Badges come from shared state (`AcolyteSdk.inbox` for Requests), never from a screen.
5. A new top-level section: add it to `nav/Section.kt` (group, gating operation, need, part; `ApiContractTest.sectionsMatchTheSpec` checks the operation), then Android `Destinations.kt` + `Routes.kt` + `AppNavHost.kt` (the `when` is exhaustive) and iOS `SectionID` + `title`/`symbol` in `Routes.swift`. Visibility is computed in `Account.shows`, tabs in `Account.tabs`, the More list in `Account.moreGroups`: never re-derive permissions in the UI.

Tabs mirror the HolyArrs phone layout: Home, Explore, Library, Search, plus Requests for non-managers who may ask (Explore then moves to More, so there are never more than four content tabs) and a last tab "More", or "Manage" for managers (`manage_library`, `approve` or `settings`). More/Manage lists the remaining sections in the web sidebar's groups.

## Strings

English and German, on both platforms, always both:

- Android: `androidApp/src/androidMain/res/values/strings.xml` and `values-de/strings.xml` (plus the `strings_*.xml` files next to them). No hardcoded UI text (lint `HardcodedText` and `MissingTranslation` are errors; `StringsTest` checks keys, placeholders and spelling). The Android TV app has its own tables in `androidTvApp/src/androidMain/res/values*/strings*.xml`, every name prefixed `tv_`; the wording is the phone's or the iOS `tv.` keys', "Apple TV" becomes "Android TV". Only the error texts of `androidCommon` are shared.
- iOS: `iosApp/Acolyte/en.lproj/Localizable.strings` and `de.lproj/Localizable.strings`, read through `L10n.tr/format/plural` (`Support/L10n.swift`; plural keys end in `.one` / `.other`). ## iOS is compile-gated by CI

There is no Swift compile on Linux. Kotlin/Native compiles the iOS targets of `shared` locally (`shared:allTests` does), but Swift does not. Push, then read the iOS checks: `ios-build` first (shared framework plus simulator app build), then `ios-tests` (Kotlin/Native tests of `shared`); `ios-gate` is the always-reporting required check. After changing `shared/`, also check `shared:iosSimulatorArm64Test` results in CI.

Swift 6 language mode (`SWIFT_VERSION 6.0`), deployment target iOS 18. Check new Swift against these before pushing:

- Pure helpers on a `@MainActor` type (a `static` function or `static let` that only uses its arguments) are `nonisolated`, otherwise they cannot be called from synchronous or test contexts.
- Closure parameters that a `@MainActor` type runs are `@MainActor` themselves.
- `SDKClient` and the drivers in `SDK/` are the only places with `@preconcurrency import shared` and `@unchecked Sendable`. Do not let shared (SKIE) types cross actors or reach views: map them to `Sendable` structs at the boundary.
- Read Kotlin enums by name with `Mapping.key(_:)` into Swift enums whose raw values are the lowercased names without underscores: SKIE turns a Kotlin enum into a Swift enum, but inside a Kotlin `List` (or a Flow's element) it stays the Kotlin class. Nested sealed subclasses go through `onEnum(of:)` with a `default` branch. Kotlin default arguments do not exist in Swift: pass every parameter.
- Split expressions the compiler cannot type-check in time (big heterogeneous literals, long `||` chains); that failure shows up only in CI.
- Grep before adding a constant or a string key: a duplicate is only found by CI.

## tvOS is compile-gated by CI too

Same as iOS: no Swift compile on Linux. CI job `tvos-build` builds the tvOS simulator framework and the `AcolyteTV` scheme, `tvos-tests` runs `shared:tvosSimulatorArm64Test`; both are part of `ios-gate`. Use only tvOS-available SwiftUI API in `AcolyteTV/` and in the shared files above (no `refreshable`, sheets of UIKit pickers, `navigationBarTitleDisplayMode`). Use `.buttonStyle(.card)` for focusable posters and leave focus to the system. `release.yml` ships tvOS to TestFlight through its `tvos-release` job (own profile `TVOS_PROFILE_APP_BASE64`, `iosApp/ExportOptionsTV.plist`); it is skipped with a notice while that secret is missing. Debug-only `TVScreenshotLaunch.swift` opens screens for the Apple TV store screenshots (`scripts/screenshots/tvos.sh`); the demo server answers every endpoint the TV screens call, so a new TV screen in the set needs its endpoints there.

## tvOS UI (`AcolyteTV/`)

Sources: Apple HIG (Designing for tvOS, Layout, Focus and selection, Tab bars, Remotes, Playing video) and the SwiftUI docs for tvOS 18 to 27.

- **Structure**: `TVRootView` > `TVMainTabs` (one `Tab` per section from `TVSections.tabs(for:)`, computed from `AccountInfo.tabs` and `moreGroups`, never from permissions) > `TVTabHost` (own `NavigationStack`, `TVRouter`, `TVNavigator`) > `TVSectionScreen`. Settings is always a tab. Tabs are the default top tab bar: do not use `.sidebarAdaptable` (on tvOS it always shows a sidebar). Tab labels are text only (Settings is the gear icon alone): the bar is capped in width and clips a seventh tab with icons. Each section has one file `TV<Area>View.swift` taking `account`; a placeholder until built. Do not add a `NavigationStack` inside a tab screen.
- **Navigation**: only through `@Environment(TVNavigator.self)`: `open(Route)`, `open(SectionID)`, `openCard(DiscoverCardInfo)`. `TVRouteScreen` decides what a `Route` shows; routes the TV does not support land on `TVOpenOnPhoneView` (add a case there to support one). `.ask` opens `TVAskView` as a full-screen cover owned by the router (`TVRouter.ask`).
- **Layout**: SwiftUI already insets by the tvOS safe area (60 pt top and bottom, 80 pt sides): never pad it again; only backdrops use `ignoresSafeArea()`. All sizes come from `Theme.TV` (`TVMetrics.swift`): posters 260x390 (six per row), backdrop cards 410x231 (four per row), gutter 40, `focusPad` 30 around every focusable row so the focus scale is not clipped. Horizontal rows are `TVShelf` (lazy, `scrollClipDisabled`, `focusSection`), never a hand-made `ScrollView`.
- **Focus**: store screenshots start from a Debug-only `screenshotFocus` hook (`Support/TVScreenshotFocus.swift`, launch argument `-acolyte_screenshot_focus 1`) that focuses the first card or action once the page is loaded; never use it or `FocusState` writes for release behaviour. Every control must be reachable by focus. Use `.buttonStyle(.card)` for artwork, `.bordered` / `.borderedProminent` for actions (`TVActionButton`), `.borderless` for round images; never custom focus rings or manual scaling. Do not move focus yourself (no `@FocusState` hacks, no `defaultFocus` unless a screen has no obvious first control). Menu returns to the tab bar and pops screens: do not intercept it except in full-screen players (`onExitCommand`). Disabled controls cannot be focused, so show state in text as well.
- **Text**: system text styles only (`.callout`, `.footnote`, `.headline`, `.title2`), no fixed font sizes except icons; keep copy short, it is read from across the room. No pull to refresh: errors and empty states carry a focusable retry or reload button (`TVStatusContent`).
- **Look** (cinema dark, our `Theme` palette with the HolyArrs red as the only accent; reference screenshots of an existing tvOS client for HolyArrs: `Docs/screenshots/tvos-home.jpg`, `tvos-title.jpg`, `tvos-show.jpg`, `tvos-explore.jpg`, `tvos-searchq.jpg`, `tvos-calendar.jpg`, `tvos-askshow.jpg` in github.com/mathiash98/holyarrs-apple; inspiration only, never copy code): pages are edge to edge. A page that is about one title has a `TVBackdropLayer` behind it (crisp with gradients for billboards, `blurred: true` as the ambient picture of the focused title on list pages, cross-faded when the title changes) and compact text over it. Rows are landscape `TVBackdropCard` tiles with the title logo on them and the status mark in the bottom corner (`showsText: false` when the logo says it all); posters only for dense catalogue grids. Home is a billboard (logo, `year · kind · genres`, overview) with the Featured row along its bottom where focus starts; the billboard and backdrop follow focus through one `@FocusState<String?>` and `TVFocusKey` (see `TVHomeView`). Title pages hide the tab bar (`toolbarVisibility(.hidden, for: .tabBar)`), put small `TVStatusChip` pills above the meta line and a row of neutral capsule `TVActionButton`s (primary action first so it takes focus) below the overview, then one `TVShelf` per topic (round cast cards, seasons and episodes, similar). Dialogs are full-screen covers with large `.card` option tiles (`TVModeTile`), toggles and capsule buttons, one focus section per group.
- **Components** (`Support/`): `TVPosterCard`, `TVBackdropCard` (stills, `detail`, `chip`, `badge`, `focus`), `TVPersonCard`, `TVShelf`, `TVCardRow` (a `CardRowInfo`), `TVDiscoverCard`, `TVTitleCard`, `TVBackdropLayer`, `TVStatusContent` / `TVLoadingView` / `TVErrorView` / `TVEmptyView`, `TVStatusChip`, `TVChip` (selectable), `TVChipRow` (focus-section row of chips), `TVThumbCard` (poster thumbnail with text lines; lists use `LazyVGrid(columns: Theme.TV.thumbColumns)`), `TVNoteBanner` (confirmation or failure line with optional Undo), `TVNoticeBanner`, `TVActionButton`, `TVOpenOnPhoneView`. Images through `AuthImage` only.
- **Browse pages** (`Support/TVBrowse.swift`, `TVBillboard.swift`, `TVDiscoverRows.swift`): `TVBrowsePage` is a billboard that follows focus (hero, optional header, content closure gets the `FocusState` binding; give cards a `TVFocusKey` and pass a `[focus id: DiscoverCardInfo]` lookup from `TVFocusLookup.cards`), `TVAmbientPage` is the blurred-ambient variant for grids and lists, `TVDiscoverRows` renders a presenter's rows (top services, genres, cards), `TVBrowseTile` is a category tile, `TVPosterGrid` a six-column poster grid. Cards take a long-press `menu` (`TVMenuAction`) for the ask/add action. Browse screens live in `AcolyteTV/Browse/`.
- **Video**: `VideoPlayer` in a `fullScreenCover` (see `TVTrailerPlayerView`), HLS headers through `AVURLAssetHTTPHeaderFieldsKey`; there is no browser on tvOS, so never `openURL` a web page.
- **Never**: manager tools, long forms (use option tiles, chips and toggles), keyboards where a choice list works, `refreshable`, UIKit pickers, `contextMenu(preview:)`, `navigationBarTitleDisplayMode`. Anything newer than tvOS 18 goes behind `if #available` and must look right without it. Strings use the `tv.` prefix unless an existing key says the same.


## Android TV UI (`androidTvApp/`)

The counterpart of `AcolyteTV`: the same sections, look and shared presenters, built with Compose for TV (`androidx.tv:tv-material` 1.1: `Card`, `Button`, `FilterChip`, `TabRow`, `ListItem`, `Switch`; lazy lists, `focusRestorer`, text fields and navigation are the regular Compose libraries). Same `applicationId` as the phone app (one Play listing), `versionName` from `APP_VERSION`, `versionCode` = the phone's formula + 500, landscape only, `LEANBACK_LAUNCHER`, no touch screen, so everything runs on D-pad focus. The two Android apps never share screens, only `androidCommon`. Nothing of the TV app has run on a TV: neither CI nor the dev machine has an Android TV emulator (no KVM), so the module is compiled, linted and unit tested, and `TvScreensTest` (Robolectric, 960x540 dp at 2x) composes the main screens with fake state and writes PNGs to `androidTvApp/build/tv-screens/` (CI uploads them with the test results); look at them after UI changes. TV Material controls react to the D-pad, not to touch: in tests give a node focus with `requestFocus()` and press it with `performKeyInput { pressKey(Key.DirectionCenter) }` (`performClick()` does nothing). `TvLiveTest` signs in through the real screens against a live server and is skipped without `ACOLYTE_LIVE_URL`: `export ACOLYTE_LIVE_PORT=6277; eval "$(scripts/api/live-server.sh)"` (pick a free port; the container name is `ACOLYTE_LIVE_CONTAINER`), then `./gradlew androidTvApp:testDebugUnitTest --tests '*TvLiveTest*'`.

- **Structure**: `TvApplication` (SDK, Coil loader) > `TvActivity` > `TvApp` (`SessionViewModel`: Restoring splash, `TvSignInScreen`, `TvMain`) > `TvMain` (one `NavHost`, start `TabsRoute`) > `TvMainTabs` (top `TabRow`, one tab per `TvSections.tabs(account)`, computed from `Account.tabs` and `moreGroups`, never from permissions, Settings always last) > `TvSectionScreen(section, account)`. Do not add a `NavHost` inside a section screen. There is one nav graph: `TabsRoute` (the tabs), `TitleRoute`, `AskRoute`, `PersonRoute`, `CollectionRoute`, `GenreRoute`, `BrowseRoute`, `SectionRoute` (sections that are not tabs, `TvSections.pushed`, today `POPULAR`) and `PhoneRoute` (the "open on phone" screen). Title and the other detail routes are full screens without the tab bar.
- **Navigation**: only through `LocalTvNavigator.current` (`nav/TvNavigator.kt`): `openTitle(kind, tmdb, libraryId)`, `openAsk(kind, tmdb, fourK)`, `openPerson`, `openCollection`, `openGenre`, `openBrowse(link)`, `openSection(section)` (selects the tab, or pushes `SectionRoute`, or lands on "open on phone"), `openCard(card)`, `openOnPhone(section | topic)`, `back()`. A route the TV does not support lands on `TvOpenOnPhoneView`. Back: inside a tab it moves focus to the tab row, then to Home, then leaves the app; pushed screens pop. Full-screen overlays that are not routes (the trailer) are a `Dialog` owned by the screen that opens them.
- **Layout**: all sizes, the type scale and the colours are in `theme/TvTheme.kt` (`TvMetrics`, `TvType`, `TvColors`, `TvTheme`); no other file hardcodes a size or a colour. The metrics are the tvOS ones in dp (1 pt = 0.5 dp on a 1080p screen): posters 128x192 (six per row), backdrop cards 200x112 (four per row), gutter 16, `focusPad` 14 around every focusable row so the focus scale is not clipped, `marginX` 48 and `marginY` 27 for overscan. Pages are edge to edge: a page does not pad its horizontal margin, every component pads itself (`Modifier.tvPageInset()` for text, `contentPadding` for rows), so rows scroll to the screen edge and the focus scale is never clipped. Backdrops use `TvBackdropLayer` behind the page.
- **Focus**: use the TV Material components (`Card`, `Button`, `FilterChip`, `Tab`, `ListItem`), never custom focus rings or manual scaling (`TvCardSurface` is the one wrapper around `Card`: scale, white focus border, shape). Every control must be reachable by D-pad and disabled controls cannot be focused, so show state in text as well. Horizontal rows are `TvShelf` (`LazyRow` with `focusRestorer`), never a hand-made scroller. Do not move focus yourself except to give the first action of a pushed screen (title page, dialogs, error and empty states) a `FocusRequester`; never request focus in tab content (it would steal it from the tab row). Group related controls with `focusGroup()`. Text fields (`TvTextField`) open the keyboard on select; keep forms to a few fields and prefer chips, tiles and toggles.
- **Scrolling**: `TvTheme` replaces Compose's default bring-into-view (it pivots every focused item to 30 percent of the list and scrolls a billboard away) with a minimal one: scroll only as far as the requested rectangle needs, and align its top when it is taller than the viewport. The rectangle is the whole row, not the focused card: `Modifier.tvRowBounds()` (`components/TvFocus.kt`) makes a row report its own bounds plus `marginY` above and below, so the header, the card with its focus scale and the text under it are fully inside the safe area when a card takes focus. `TvShelf`, `TvChipRow`, `tvThumbRows`, `tvPosterGrid`, the search tile and people lines, the title hero, the Home billboard and the Explore hero have it; put it on any new row or section that is not one of these (the modifier goes on the row's outer layout, above the lazy row). `TvCardSurface` adds `tvFocusSlack()` (`focusPad` of room around a card for the horizontal scroll). Blurred or scaled layers must `clipToBounds()` (an ambient backdrop once covered the tab bar). `TvStatusContent` and `TvAmbientPage(scrimTop = true)` draw a short gradient scrim over the top `scrimHeight` of a scrolling page (`tvTopScrim()`), so rows that scroll away under the tab row or the screen edge fade out instead of being cut (no offscreen layer: dimmed rows are layers already). `TvScreenshotLaunch` (debug only; extras `screenshot_server`, `screenshot_user`, `screenshot_password`, `screenshot_open` = section name, `title:<kind>:<tmdb>`, `person:<id>`, `genre:<type>:<id>`) is driven by `scripts/screenshots/androidtv.sh` in the Store Screenshots workflow, which is also the TV app's emulator smoke test (it also writes `focus-*` screenshots with the remote scrolled down to the logs artifact).
- **Dimming**: a page that wants the focused row to stand out provides `LocalTvRowFocus` (`TvRowFocus`); every `TvShelf` below it fades to `TvMetrics.DIM_ALPHA` while another row has focus and is at full strength while focus is outside the rows (tab row). Home and `TvBrowsePage` (Explore, New & Popular, genre) provide it.
- **Fixed heights**: never give a block of text and buttons a fixed height (`fillParentMaxHeight` on a column that holds the overview and the action row squeezes the buttons to nothing on a real show). Use a minimum (`heightIn(min = ...)`); the title hero does. A row of actions is computed by a pure function (`tvTitleActions`) with a label for every action and is not shown when empty.
- **Following focus**: a card takes `onFocus`. `TvBrowsePage` (billboard that follows the focused card, content lambda gets `onFocusCard`), `TvAmbientPage` (blurred ambient backdrop, content lambda gets `onFocusImage`) and `TvHomeScreen` collect those callbacks. Give every card of a page the callback, `TvCardRow` and `TvDiscoverCard` already take it.
- **Text**: `TvType` styles only (`callout`, `footnote`, `headline`, `title`), no inline font sizes except icons; copy is short, it is read from across the room. No pull to refresh: errors and empty states carry a focusable retry or reload button (`TvStatusContent` focuses it).
- **Components** (`components/`): `TvPosterCard`, `TvBackdropCard` (stills, `detail`, `chip`, `badge`, `logo`, `showsText`), `TvPersonCard`, `TvThumbCard`, `TvDiscoverCard` and `TvCardRow` (a `CardRow` of `DiscoverCard`s, long press opens the add or ask action through `TvMenuAction`), `TvTitleCard`, `TvShelf`, `TvChipRow`, `TvBackdropLayer` (crisp or `blurred`, cross-fades when the picture changes), `TvBillboard`, `TvBrowsePage`, `TvAmbientPage`, `TvBrowseTile`, `TvStatusContent` / `TvLoadingView` / `TvErrorView` / `TvEmptyView`, `TvStatusChip`, `TvChip` (selectable), `TvActionButton` (capsule, `prominent` for the primary one), `TvModeTile`, `TvToggleRow`, `TvTextField`, `TvConfirmDialog`, `TvMenuDialog`, `TvNoteBanner`, `TvNoticeBanner`, `TvOpenOnPhoneView`, `TvPlaceholderView`. Pictures through `ServerImage` only. The card text helpers (`tvCardLine`, `tvFreshText`, `tvMarkText`, `tvGenreText`) are in `TvDiscoverText.kt`. Browse pieces: `tvDiscoverRows` (`LazyListScope` extension that renders a presenter's rows: top services, genre tiles, card rows), `TvChipShelf` (card row with service chips and optional rank badges), `TvTypeChipRow`, `TvServiceChips`, `tvPosterGrid` (six poster columns as lazy rows of cards, never a nested grid), `TvBrowseListView` (generic mood and category list), `TvInlineLoading` (spinner for a lazy item); their words are in `TvBrowseText.kt`. `TvBrowsePage` leaves insets to its `header` (chip rows pad themselves, banners take `tvPageInset()`). Paged lists load the next page from a `LaunchedEffect(rows.size)` in a last `more` item.
- **Never**: manager tools, long forms, touch-only gestures, a `NavHost` or `NavController` in a screen, `pullToRefresh`, hardcoded sizes, colours or strings, a second theme file, own copies of the palette, `ServerImage` or the error texts (they live in `androidCommon`).
- **Screens**: Home (`TvHomeScreen`: billboard with the Featured row at its bottom, then rows and Coming up), Settings (server, account, sign out), the title page (`title/`: hero, shelves, season chips and episodes, trailer in Media3 `TvTrailerPlayer`), the ask dialog (`ask/TvAskScreen`, a full screen route), sign-in (`signin/`: server, name and password, two-factor, Jellyfin and Emby through the way list; Plex, single sign-on, setup and reset land on a "finish on your phone" step). Explore, New & Popular, Search and the detail pages person, genre, collection and browse list (`explore/`, `popular/`, `search/`, `browse/`; Search types with `TvTextField` and the TV keyboard, filters are chips, genre tiles show when the query is empty). Requests (`requests/`: tabs and filter chips, a two-column grid of `TvThumbCard`s, the confirmation and undo line `TvNoteBanner`, a `TvMenuDialog` per card for open, approve, decline and take back, approve all behind `TvConfirmDialog`), Calendar (`calendar/`: month bar, type and follows chips, one `TvShelf` of `TvBackdropCard`s per day) and Downloads (`downloads/`: tab and sub chips, status line, a grid of `TvThumbCard`s that open the title; no controls, as on tvOS). Their screens follow the pattern in the next bullet (`Tv<Area>Content(state, actions)` plus a `Tv<Area>Actions` interface the ViewModel implements, so tests can record calls) and use `tvThumbRows` (`components/TvThumbGrid.kt`) for the two-column grids inside the page's `LazyColumn`. One file per section screen, all `@Composable fun Tv<Area>Screen(account: Account)` registered in `TvSectionScreen` (`nav/TvMain.kt`).
- **Adding a section screen**: replace the body of its `Tv<Area>Screen.kt` (the only file you need to touch besides strings and tests). A `viewModel { }` per screen holds the presenter from `LocalSdk.current` (`init { load() }`, `suspend fun watch()` run with `repeatOnLifecycle(STARTED)`, actions in `viewModelScope`; see `TvHomeViewModel`), split the screen into a thin function that collects the state and a `Tv<Area>Content(state, ...)` that only renders it, so `TvScreensTest` can compose it with fake state (add a test and look at the PNG). Words for the area go in a `Tv<Area>Text.kt` next to the screen. Words and strings the phone shows identically live in `androidCommon` (`ui/requests/RequestsWords.kt`, `ui/downloads/DownloadsText.kt`, `CalendarWords.kt`, strings in its `strings_requests.xml` and `strings_downloads.xml`, referenced as `CommonR` from both apps): put a new shared label or word table there, not in either app. Strings: `androidTvApp/src/androidMain/res/values/strings_<area>.xml` and `values-de/strings_<area>.xml` (own file per area, so parallel work does not conflict), names `tv_<area>_...`, wording from the phone's `strings.xml` or the iOS `tv.` keys. Cards and rows open things through the navigator, never through the nav controller.

## API spec contract

- `api/openapi.json` is byte for byte the spec of the HolyArrs release in `api/VERSION` (`api.yml` job `spec`). Move to a new release only with `scripts/api/update-spec.sh [tag]`: it prints what changed for the endpoints the app uses, writes both files and runs the contract test. Then run the live test and fix models in the same change.
- `api.yml` jobs `spec`, `contract` and `live` block PRs (`api-gate`); `drift` runs weekly and on demand, compares the pinned spec with the latest release and upstream `main`, writes the job summary and opens or updates the `api-drift` issue when a newer release exists or an operation the app uses changed.
- The live job boots `holyarrs/holyarrs:<api/VERSION>`, completes first-run setup over the API (`scripts/api/live-server.sh`), signs in with a password and with an API key, and calls every registered read endpoint without path parameters, decoding with and without coercion.
- Plugins (`/api/v1/plugins*`, `/api/v1/plugin-*`) are out of scope; the contract test refuses them.

## Promo images

`scripts/store/make-promo.py` (Pillow, numpy, Inter in `scripts/store/fonts`) draws the README banner and strips, the website pictures (`site/assets/img`), the sharing pictures, the store header images, the Play feature graphic and Android TV banner and the captioned screenshots (`assets/store/captioned`) from `store/screenshots/`. Never edit those images by hand: change the script and rerun it. The `commit` job of `store-screenshots.yml` reruns it, so a refresh pull request already carries the redrawn files. Devices are drawn by the script (plain bezels, no manufacturer artwork); keep it that way.

## CI and release

`android.yml` (phone, TV and `androidCommon`), `ios.yml` and `api.yml` gate every PR; `release.yml` ships signed builds when a GitHub release is published (secrets table in the README; it fails in its first step and names any missing secret). Actions are pinned to commit SHAs with a version comment: keep that when bumping. Signing material (`*.jks`, `*.p12`, `*.p8`, `*.mobileprovision`) is gitignored and must never be committed. `iosApp/ExportOptions.plist` has no team id (the workflow injects it) and its profile name `Acolyte App Store` must match the provisioning profile. `ExportOptionsTV.plist` likewise with `Acolyte tvOS App Store`. The `platforms` list of `release.yml` is computed in `release-exists`: a new platform is an input option, a word in that list and an `if` on its job (`android` and `androidtv` are separate words: test them with the surrounding spaces). The Android TV job ships `acolyte-tv-<version>`; its versionCode is the phone's plus 1,000,000,000 and its Play upload (`tv:internal`) is non-fatal until the TV form factor is enabled in the Play Console.

## Git

Commit style: lowercase imperative, short first line, details in the body if needed (e.g. `add library screen`). Never add `Co-Authored-By` or any attribution line. Stage files by path, not with `git add -A`.

## Settings

- `feature/settings/SettingsCatalog.kt` lists every settings page with its gate (permission, part, held feature); the Settings home, search and attention dots come from `SettingsHomePresenter`. A new page: add it to `SettingsPage`, a `Settings<Page>Route` (Android) / `Route.settings<Page>` (iOS), strings `settings_page_<key>` and `_about`.
- Risky writes answer `403 reauth`: take the account `ReauthGate` (`AcolyteSdk.reauthGate()`, kept as `val reauth` on the presenter) and wrap them in `reauth.guardError(onFailure, onCancel) { ApiError? }` (or `reauth.guard { ApiResult }`). The call suspends while the prompt shows and retries once. UI: Android `ReauthSheet(presenter.reauth)`, iOS `ReauthStore` + `.reauthSheet(store.reauth)`; there is no settings copy of the prompt.
- Files go through `Api.download` / `Api.upload` (streamed to the temp folder), then the share sheet (`shareTransferredFile`, `ActivityShareSheet`); call `clearTransfers()` afterwards.
- Spec gaps of settings endpoints live in `contract/Gaps<Area>.kt`, not in `KnownSpecGaps`.
